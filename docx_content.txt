2. Antigravity Build Instructions

First inspect the existing website and project files. Identify the current framework, routing, reusable components, assets, forms and integrations before editing.

Upgrade the existing website in place. Do not discard working functionality or rebuild everything from scratch unless the existing implementation is demonstrably unusable.

Use the content and section order in this document as the approved source. Do not invent company history, project counts, client logos, certifications, manufacturer names, addresses, phone numbers, awards or performance statistics.

Use the existing Avenrix logo and approved brand assets if available. Do not create a substitute logo or alter the logo proportions.

Use a premium blue-and-white corporate visual system: navy headings, clear blue accents, white backgrounds, pale-blue section surfaces, restrained borders and subtle shadows.

Use real, relevant healthcare infrastructure photography. Prefer actual Avenrix/manufacturer images when supplied. If temporary stock imagery is needed, use the image references in this document and keep image assets replaceable.

Do not use unrelated medical stock imagery (for example, doctors smiling at camera) as a substitute for actual infrastructure or products. Product imagery must accurately represent the named product.

Build responsive layouts for desktop, tablet and mobile. Ensure navigation, product cards, forms, buttons, tables and images work at narrow widths.

Use restrained motion: subtle fades, gentle reveal transitions and hover states. Avoid excessive parallax, 3D objects, oversized animated text, cursor gimmicks and distracting transitions.

Keep accessibility in mind: semantic headings, keyboard-accessible navigation, visible focus states, sufficient contrast, descriptive image alt text and properly labelled form fields.

Optimize images, lazy-load below-the-fold media, avoid layout shifts and keep page performance strong.

Every CTA must work. Forms must validate input and use the existing approved submission integration. Do not display a fake success message or claim delivery unless the backend confirms success.

Preserve existing analytics, SEO metadata and integrations where functional. Add or improve page titles, meta descriptions, canonical URLs, Open Graph metadata and structured data only when the information is verified.

After implementation, test all navigation links, product links, enquiry forms, phone/email/WhatsApp actions, brochure downloads, mobile breakpoints and browser console errors.

9. Claims, Accuracy & Content Guardrails

Do not invent years of experience, completed projects, installed capacity, client names, testimonials, manufacturer partnerships or geographic coverage.

Do not claim Avenrix is a manufacturer if its operating model is sourcing and manufacturing partnerships.

Use 'turnkey' with scope clarity. Explain that installation, commissioning and related services depend on the agreed project scope and partner capabilities.

Do not claim all products are certified, NABH-approved, ISO-certified, CE-certified or compliant unless the exact product documentation supports the statement.

Do not publish generic technical performance values such as HEPA efficiency, pressure differentials, air-change rates or ISO cleanroom classifications as universal guarantees. Display only project- and product-specific verified values.

Do not imply that NABH accredits Avenrix products. If mentioning NABH, refer accurately to supporting healthcare facility infrastructure requirements.

Use 'we coordinate', 'we facilitate' or 'we support' where the service is delivered through partners; use direct delivery claims only when confirmed.

Confirm the legal company name, contact details, address, domain and social profile URLs before publishing.
